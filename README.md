# سامانه یکپارچه مدرسه مشاهیر آینده — فاز اول (دبیرستان)

بک‌اند: Laravel 13 + PHP 8.3+ + PostgreSQL (`backend/`) — فرانت: Vite + React 19 + TS + Tailwind 4 (`frontend/`). ردیس اختیاری است.
کنترل دسترسی فقط سمت سرور، مبتنی بر یک فایل واحد ماتریس مجوزها؛ پیش‌فرض ممنوع؛ خارج از محدوده = ۴۰۴.

## اجرای محلی

پیش‌نیاز: PHP 8.3+ با اکستنشن‌های `pdo_pgsql`, `mbstring`, `intl`, `bcmath`, `zip`, `fileinfo`؛ Composer 2؛ Node.js 22+؛ PostgreSQL 16+ (در این پروژه لوکال روی پورت 5433). ردیس لازم نیست.

```bash
# ۰) دیتابیس mashahir را روی 5433 بساز (یا DB_* را در .env عوض کن)

# ۱) بک‌اند
cd backend
composer install
cp .env.example .env                 # فقط بار اول
php artisan key:generate             # فقط بار اول؛ بعداً عوض نکن (PhoneHash به APP_KEY وابسته است)
# اگر ردیس نداری، در .env: SESSION_DRIVER=file / CACHE_STORE=file / QUEUE_CONNECTION=sync
php artisan migrate:fresh --seed --force
php artisan serve --port=8000

# ۲) فرانت
cd ../frontend
npm install
npm run dev                          # http://localhost:3000 (پروکسی /api → 8000)
```

`migrate:fresh` کل دیتابیس را پاک می‌کند — فقط لوکال.

## تست‌ها

# بک‌اند: نیاز به دیتابیس mashahir_test روی 5433 (مقادیر در phpunit.xml)

## ماژول‌های پیاده‌شده

- **هویت و دسترسی**: ورود OTP، تعویض نقش/مدرسه، نقش سفارشی هر مدرسه (CRUD)، ماتریس مجوزهای ۶۹تایی با ۱۶ قید شرطی
- **حضور و غیاب**: پیش‌نویس → نهایی‌سازی → اصلاح (ش۹/ش۷) + پیامک غیبت به ولی‌های دارای پرچم (ش۱۴) با وضعیت و تلاش مجدد
- **تکالیف**: تعریف (با پیوست صورت تکلیف تصویر/PDF)، ارسال پاسخ به‌صورت متن و/یا فایل تصویر/PDF، تشخیص دیرکرد، نمره‌دهی با بازخورد، مشاهده ولی فقط‌خواندنی
- **فایل منیجر**: آپلود متمرکز با اعتبارسنجی محتوایی از بایت‌های فایل (فقط JPG/PNG/WebP/PDF، حداکثر ۱۰MB — پسوند دروغ‌گو رد می‌شود)، ذخیره خصوصی + checksum، استریم با کنترل دسترسی مبتنی بر ارجاع فایل
- **آزمون آنلاین**: طراحی تستی/تشریحی، ذخیره خودکار نسخه‌ای، تایمر سرور، تصحیح خودکار/دستی، پاسخ تشریحی به‌صورت تصویر/PDF برگه دست‌نویس، ش۶ visibility
- **نمره و کارنامه**: چرخه تأیید/انتشار، نسخه‌بندی کارنامه، تغییر با دلیل (append-only)، PDF
- **اعلان‌ها**: کانال رسمی با هدف‌گیری، مرکز اعلان با تب‌ها، تنظیمات کانال (ش۱۴)
- **خانواده**: پیوند ولی با پرچم‌های مستقل، حکم دادگاه (غلبه بر پرچم‌ها)، لیست تحویل‌گیری (ش۱۳ پیشنهادی)، رضایتنامه با سیاست یک/دو‌ولی
- **کلاس آنلاین**: اسکای‌روم — `SKYROOM_DRIVER=fake` برای دمو؛ `skyroom` برای سرویس واقعی با `SKYROOM_API_KEY` (URL خودکار ساخته می‌شود) یا `SKYROOM_URL` کامل — هم‌تراز با نمونه رسمی [SkyroomOnline/webservice](https://github.com/SkyroomOnline/webservice)
- **پذیرش و پیش‌ثبت‌نام**: فرم عمومی لندینگ (بدون ورود، throttle) با نرمال‌سازی ارقام فارسی → کد رهگیری `MA-XXXXXX`، اعلان درون‌برنامه‌ای به مدیر، صف بررسی مدیر/مسئول دفتر (`/pre-registrations`) با تغییر وضعیت و یادداشت + Audit
- **مدارس و چندمدرسه‌ای**: دفتر مدارس مدیر پلتفرم (`schools.manage`) — ایجاد/ویرایش مدرسه و انتصاب مدیر از میان کاندیداهای مجاز؛ جابه‌جایی مدرسه برای کادر چندمدرسه‌ای از پروفایل
- **سرویس مدرسه**: خطوط با راننده و ایستگاه‌های دارای ساعت، تخصیص دانش‌آموز به خط/ایستگاه، «مسیر من» برای راننده و ثبت سوار/پیاده‌شدن یا غیبت روزانه (راننده فقط خط خودش)
- **مشاوره**: درخواست نوبت دانش‌آموز/ولی، زمان‌بندی و تکمیل توسط مشاور (حضوری/آنلاین)، خلاصهٔ قابل‌اشتراک + یادداشت محرمانه که فقط در دامنهٔ `counseling.manage` دیده می‌شود
- **انجمن اولیا**: جلسات با دستور جلسه، صورت‌جلسه و مصوبات؛ نظرسنجی با سقف یک رأی برای هر خانواده
- **سایر**: برنامه هفتگی، ورود CSV با خطای سطری، تنظیمات مدرسه، لاگ append-only

## دپلوی (پروداکشن)

دو آرتیفکت جدا داریم: API لاراول (PHP-FPM + Nginx + PostgreSQL) و SPA استاتیک (`frontend/dist`). لاراول خودش SPA را سرو نمی‌کند (`routes/web.php` فقط welcome دارد).

پیشنهاد: یک دامنه — فرانت روی `/` و API روی `/api`. این‌طور `VITE_API_URL` خالی می‌ماند (same-origin) و CORS لازم نیست. احراز هویت Bearer token است، نه کوکی.

```bash
# بک‌اند
cd backend
composer install --no-dev --optimize-autoloader
cp .env.example .env && php artisan key:generate
# .env: APP_ENV=production, APP_DEBUG=false, APP_URL=https://<domain>, DB_* واقعی
php artisan migrate --force
php artisan db:seed --force        # فقط RBAC؛ دمو در پروداکشن seed نمی‌شود
php artisan optimize
chown -R www-data storage bootstrap/cache

# فرانت
cd ../frontend && npm ci && VITE_API_URL="" npm run build   # خروجی: dist/
```

سه نکته‌ای که قبل از بهره‌برداری باید حل شود:

1. **پیامک واقعی هنوز پیاده نشده** — `backend/app/Support/Sms/SmsManager.php` فقط درایورهای `log` و `array` را می‌شناسد؛ با `SMS_DRIVER=log` کد OTP فقط در `storage/logs/laravel.log` نوشته می‌شود.
2. **اولین کاربر باید دستی ساخته شود** — ورود فقط OTP است و seed پروداکشن کاربر نمی‌سازد (نمونه tinker در `backend/README.md`).
3. **`APP_KEY` را بعد از شروع کار عوض نکن** — `PhoneHash` با آن HMAC می‌شود و شماره‌ها `encrypted` هستند.

Queue worker و cron لازم نیست: هیچ Job واقعی و هیچ `schedule()` در کد نیست. فایل‌ها روی دیسک خصوصی `local` ذخیره می‌شوند، پس `storage:link` هم لازم نیست. جزئیات کامل (Nginx، متغیرهای محیطی، بکاپ) در `backend/README.md` و `frontend/README.md`.

## قوانین غیرقابل‌مذاکره

پیش‌فرض ممنوع؛ کنترل فقط سمت سرور؛ `school_id` روی همه مدل‌ها (خارج از محدوده = ۴۰۴)؛ ماتریس مجوزها یک فایل واحد که Seeder و تست‌ها می‌خوانند؛ UTC/timestamptz (شمسی فقط نمایش)؛ ورود فقط OTP؛ موبایل/کد ملی رمزنگاری‌شده؛ ulid برای شناسه‌های بیرونی.
